## Key concepts

### CSRs are not memory

CSRs (Control and Status Registers) live in a separate 12-bit address space inside the CPU core itself — distinct from general-purpose registers (`x0`–`x31`) and from memory. The address `0x301` (for `misa`) is a CSR address, not a memory address. You cannot read or write CSRs with load/store instructions. Attempting to dereference `0x301` as a pointer is wrong and will fault.

### CSR instructions (Zicsr extension)

RISC-V provides dedicated instructions for CSR access: `CSRRW`, `CSRRS`, `CSRRC` and their immediate variants. `csrr` and `csrw` are pseudoinstructions built on top. The CSR address is encoded as a 12-bit immediate directly in the instruction — it is not a runtime value. Two actors read/write CSRs: the hardware (automatically, on traps — writing `mepc`, `mcause`, `mtval`, updating `mstatus`) and software (explicitly, via CSR instructions).

### GCC extended inline assembly

To call a CSR instruction from C, you need GCC extended inline assembly. The pattern for reading a CSR into a C variable:

```c
uint64_t val;
__asm__ volatile ("csrr %0, misa" : "=r"(val));
```

- `%0` — refers to the first operand (zero-indexed)
- `"=r"` — output constraint: `=` means write-only (output), `r` means any general-purpose register
- `(val)` — the C variable to receive the result
- `volatile` — prevents GCC from optimising away the read (important for hardware registers that have side effects or change independently)

### Register width matters

`misa` is a 64-bit register on RV64. Using `unsigned int` (32-bit) to hold the result silently truncates the upper 32 bits, which is where the MXL field lives (bits 63:62). The fix is `uint64_t` from `<stdint.h>`. `print_hex` and `print_hex_recurse` were updated to accept `uint64_t` accordingly.

### Decoding `misa`

The register has two parts:
- **MXL** (bits 63:62): encodes XLEN. `10` = 64-bit. Confirmed RV64.
- **Extensions** (bits 25:0): one bit per letter, A=bit0 through Z=bit25.

QEMU `virt` reports: **A, C, D, F, H, I, M, S, U**

| Extension | Meaning |
|-----------|---------|
| A | Atomic |
| C | Compressed instructions |
| D | Double-precision float |
| F | Single-precision float |
| H | Hypervisor (QEMU supports it; we won't use it) |
| I | RV64I integer base ISA |
| M | Integer multiply/divide |
| S | Supervisor mode implemented |
| U | User mode implemented |

### Privilege levels (high level)

RISC-V has three privilege levels: M (machine), S (supervisor), U (user). The kernel boots in M-mode. Eventually kernel code runs in S-mode and user programs in U-mode. Traps cause the CPU to jump to a higher privilege level to handle the event, then drop back down. S and U being present in `misa` confirms the full privilege hierarchy is implemented in the QEMU virt machine.
