## Key concepts

### Trap handling lives in the CSR sections, not a dedicated chapter

In the full privileged spec (221 pages), there is no single "trap handling" section. The hardware's behavior on a trap is described across the individual CSR entries in chapter 3: `mstatus`, `mtvec`, `mepc`, `mcause`, `mtval`. Reading those five together gives the complete picture of what happens automatically. The trap-return instruction (`mret`) is covered in §3.3.2.

### Shape of a minimal trap handler

Four distinct pieces:

1. **`mtvec` setup** — one CSR write at boot, pointing to the assembly entry point. Must happen after `sp` is initialized (see below).
2. **Assembly trampoline** — the CPU jumps here on any trap. Must save all 32 general-purpose registers before calling C, because the CPU saves nothing except what it writes into CSRs (`mepc`, `mcause`, `mtval`, `mstatus`). Necessarily assembly.
3. **C handler** — reads `mcause`, prints something useful, halts. For a minimal first version, just an infinite loop — no return needed.
4. **Assembly exit (`mret`)** — restores registers and returns. Not needed for the minimal halt-on-trap version.

The trampoline is pure mechanism (make the world safe for C). The C handler is policy.

### `mtvec` BASE field and alignment

`mtvec` stores the handler address in bits [MXLEN-1:2] (BASE), with the bottom 2 bits being the MODE field. The spec requires the handler address to be 4-byte aligned, so its bottom 2 bits are always 0. This means you can write the address directly into `mtvec` without shifting — the alignment constraint makes MODE=0 (direct) fall out naturally.

### Boot ordering: `sp` before `mtvec`

`mtvec` should be set up *after* `sp` is initialized. If `mtvec` is set before `sp` and anything traps during the BSS clear, the CPU jumps to the trap handler with a garbage stack pointer. The safe order is: set `sp`, clear BSS, set `mtvec`, call `kernel_main`.

### GAS numeric label suffixes: `f` and `b`

Numeric labels (like `1:`, `2:`) can be reused in GAS. The `f` suffix means "next occurrence forward" and `b` means "nearest occurrence backward." Without the suffix the assembler wouldn't know which instance you meant.
