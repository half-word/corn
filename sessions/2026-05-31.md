## Key concepts

### mtime and mtimecmp are memory-mapped, not CSRs

`mtime` and `mtimecmp` are registers in the CLINT (Core Local Interruptor), mapped at physical addresses — not accessible via `csrr`/`csrw`. You read and write them with ordinary pointer dereferences in C. `volatile` is required to prevent the compiler from caching or reordering the accesses.

On QEMU's `virt` machine:
- `mtime`:     `0x200bff8`
- `mtimecmp0`: `0x2004000`

The timer frequency is 10MHz (10,000,000 ticks/second). A delta of 10,000,000 fires after approximately 1 second.

### Two-level interrupt enable

A timer interrupt only fires if both of these are set:
- `mstatus.MIE` (bit 3): global machine-mode interrupt enable
- `mie.MTIE` (bit 7): machine timer interrupt enable

Either one being clear suppresses delivery. Both must be set once at startup; they do not need to be reset on each tick.

### csrrs vs csrrsi

`csrrs rd, csr, rs1` sets bits in a CSR using a mask in a general-purpose register. `csrrsi` is the immediate form — the mask is encoded directly in the instruction word (5-bit unsigned field, values 0–31). Using `rd = zero` discards the old CSR value.

- `mstatus.MIE` is bit 3 (value 8): fits in 5 bits → use `csrrsi` with `"i"` constraint
- `mie.MTIE` is bit 7 (value 128): does not fit in 5 bits → use `csrrs` with a register and `"r"` constraint

### mcause interrupt bit

Bit 63 of `mcause` distinguishes interrupts from exceptions: 1 = interrupt, 0 = exception. The remaining bits are the exception code. For a machine timer interrupt, the code is 7.

```
interrupt    = mcause >> 63
exception_code = mcause & ~(1ULL << 63)
```

### mepc advance belongs in C, not assembly

The decision to advance `mepc` is policy — it depends on what kind of trap occurred. Faults (synchronous exceptions) point `mepc` at the faulting instruction, so you advance by 4 to skip it. Interrupts point `mepc` at the instruction that was about to run; you return straight to it. This logic belongs in `kernel_trap`, not unconditionally in `boot.S`. `boot.S` now just saves, calls, restores, and mrets.

### Re-arming the timer

After handling a timer interrupt, `mtime` is still >= `mtimecmp`. The interrupt will re-fire immediately on `mret` unless you write a new `mtimecmp` value before returning. The current approach reads `mtime` at handler time and adds the delta — this works but drifts slightly (each interval is "delta after the handler ran" rather than "delta after the previous tick was scheduled"). A more precise approach would add the delta to the previous `mtimecmp` value instead.

### What this is

The loop — arm timer, enable interrupts, spin, handle interrupt, re-arm, repeat — is structurally identical to the core of a preemptive scheduler. The handler currently does nothing useful, but the mechanism is complete. Replacing "print TIMER" with "pick next process and switch context" is what turns this into scheduling.

## State of the code

`boot.S`:
- Saves all 31 GPRs, calls `kernel_trap` with frame pointer in `a0`, restores all 31 GPRs, `mret`
- No `mepc` advance — that moved to C

`kernel.c`:
- `set_interrupt()`: writes `mtimecmp = mtime + 10000000`
- `enable_interrupts()`: calls `set_interrupt`, then sets `mstatus.MIE` and `mie.MTIE`
- `kernel_main`: calls `enable_interrupts()`, then spins
- `kernel_trap`: reads `mcause`, branches on interrupt bit and exception code; timer path prints "TIMER!" and re-arms; fault path prints debug info and advances `mepc`
