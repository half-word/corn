## What to understand before continuing

Two open questions were left deliberately unresolved — worth sitting with before the next session:

1. **Pointer width matters for MMIO.** Why `char *` and not `int *` when writing to the UART? The pointer type controls the access width (byte vs word). Writing a 4-byte word to a register that expects a byte can produce wrong behavior or be ignored by the hardware.

2. **`volatile`.** The C compiler doesn't know `0x10000000` is special hardware. It may legally cache the write in a register, reorder it, or optimize it away entirely if it determines the value is never read back. The `volatile` keyword prevents this. Look up what `volatile` guarantees and what it doesn't — it's frequently misunderstood. The MMIO pattern should be `volatile char *`.

## State of the code

`kernel.c` currently has the raw unqualified pointer. Before adding more UART functionality, fix it to use `volatile`.
