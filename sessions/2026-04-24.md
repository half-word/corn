## Key things learned

### RISC-V instructions

- `auipc rd, imm` — PC-relative upper immediate load: `rd = PC + (imm << 12)`. Used with `addi` to form PC-relative addresses in two instructions.
- `lui rd, imm` — absolute upper immediate: `rd = imm << 12`. Used to load the UART base address `0x10000000`.
- `jal rd, offset` — jump and link; saves return address in `rd`. `j` is the pseudo-instruction `jal x0, offset` (discard return address). `jal ra, target` is the standard call instruction.
- `jalr rd, offset(rs)` — indirect jump and link. `ret` is the pseudo-instruction `jalr x0, 0(ra)`.
- `sd`, `ld` — store/load doubleword (8 bytes). `sb`, `lbu` — store/load byte (unsigned).
- `bgeu t0, t1, label` — branch if t0 >= t1 (unsigned).
- `bnez rs, label` — pseudo-instruction for branch if rs != 0.
- `x0` / `zero` — hardwired zero register; writes to it are discarded.

### Function prologue/epilogue

Unoptimized RISC-V functions mechanically:
1. Decrement `sp` to allocate a stack frame
2. Save `ra` and any callee-saved registers (e.g. `s0`/`fp`) to the stack
3. Set `s0` (frame pointer) to the old `sp` for stable local variable addressing
4. On return: restore saved registers, increment `sp`, execute `ret`

An optimizing compiler omits the frame pointer and avoids saving `ra` in leaf functions (functions that make no calls).

### BSS zeroing loop

`_start` zeroes BSS by iterating from `__bss_start` to `__bss_end` in 8-byte steps using `sd zero, 0(t0)`. Required by the C standard, which guarantees uninitialized globals and statics are zero-initialized before `main` runs.

The loop is currently a no-op because BSS is empty (`__bss_start == __bss_end`).

### BSS alignment bug (fixed this session)

The zeroing loop uses `sd` (8-byte store), which requires the address to be 8-byte aligned on RISC-V — unaligned accesses trap. Without explicit `ALIGN(8)` in the linker script, `__bss_start` could land at an unaligned address (e.g. `0x80000086`) the moment any global variable is added, causing a trap on the first loop iteration. Added `ALIGN(8)` before `__bss_start` and after the BSS contents (before `__bss_end`) to enforce both start alignment and size-as-multiple-of-8.

### PC-relative vs absolute addressing

`auipc`-based addressing is position-independent — the offset between instruction and target is fixed regardless of load address. `li` / `lui`+`addi` encodes an absolute address and breaks if the kernel is loaded elsewhere. The compiler defaults to PC-relative under `-mcmodel=medany`.

### UART

On QEMU's `virt` machine the UART base address is `0x10000000` (hardware-dictated by QEMU's memory map). Writing a byte to that address sends it to the terminal. `print` loads one byte at a time from the string, writes it to `0x10000000`, and loops until it hits the null terminator.
