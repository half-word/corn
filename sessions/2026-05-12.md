## Key concepts

### Calling convention doesn't apply in a trap handler

The caller-saved / callee-saved distinction exists to coordinate between C functions. In a trap handler, the "caller" is the hardware — it doesn't follow the calling convention. The interrupted code expects all its registers intact on return, so every register except `x0` must be saved. `x0` is hardwired to zero and has no state to save.

For the current halt-on-trap version, none of this matters in practice — if you never execute `mret`, there's no state to restore. The saving is only necessary when you want to resume the interrupted code.

### `call` vs `j` to enter a C function from a trap handler

`call` sets `ra` before jumping; `j` does not. The function prologue (saving `ra`, setting up the frame pointer) is generated by the compiler *inside* the function — not triggered by the call instruction. Using `call` is the right choice for a trap handler that will eventually return, because the C handler needs `ra` set to return back into the trampoline.

### `mtvec` alignment: WARL enforcement

The spec says `mtvec` is WARL (Write Any Read Legal). If you write an unaligned address — one whose bottom 2 bits are nonzero — the implementation is allowed to silently store a different legal value. QEMU enforces this: writing `0x80000036` (bottom bits `10`) left `mtvec` as `0x0`. The symptom was the CPU jumping to address `0x0` on the first trap.

Fix: add `.align 4` (align to 2^2 = 4 bytes) before the trap label in GAS.

### Debugging a silent CSR write failure

When a CSR write appears to have no effect: check what the source register actually contains, not what you think it should contain. In this case `t0` had the right address (`0x80000036`), but the address itself was illegal for `mtvec`. `nm` is the right tool to check what symbols an object file exports; `info registers` in GDB reads CSR values directly.

### `mcause` layout

The top bit (bit 63 on RV64) is the interrupt flag: 1 = interrupt, 0 = exception. The remaining bits are the exception/interrupt code. To parse: `interrupt = mcause >> 63`, `code = mcause & ~(1ULL << 63)`. Exception code 7 is Store/AMO access fault — what you get for writing to an unmapped address (like `0x0` on QEMU virt).

## State of the code

`boot.S` has `.align 4` before the `trap` label, which `call`s `kernel_trap`. `kernel_trap` in `kernel.c` prints "Oh no!", reads and prints `mcause`, parses the interrupt bit and exception code, then halts. The null pointer dereference in `kernel_main` triggers a Store/AMO access fault (code 7), which is correctly caught and printed.

The trampoline is still minimal — no register saving, no `mret`. The wiring is solid.
