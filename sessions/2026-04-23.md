### Relocations

- What a relocation entry is and what lives in it (symbol, offset, type)
- How the compiler and linker divide the work: compiler emits relocation placeholders, linker resolves them
- Why the relocation type (`R_RISCV_HI20`) is determined at compile time, not link time
- What "truncated to fit" means precisely: the value the linker computed doesn't fit in the bit field the relocation targets

### RISC-V instruction encoding

- `lui`: loads a 20-bit immediate into bits [31:12] of a register, sign-extends to 64 bits on RV64
- `addi`: adds a 12-bit sign-extended immediate — used with `lui` to build a full 32-bit absolute address
- `auipc`: like `lui` but adds the result to the PC — the basis of PC-relative addressing
- Why `auipc`+`addi` sidesteps the sign-extension problem: the encoding is a *delta from PC*, not an absolute address, so the sign extension issue doesn't arise as long as code and data are close together

### Code models

- `medlow`: uses `lui`/`addi` absolute addressing; requires all symbols within signed 32-bit range of zero
- `medany`: uses `auipc`/`addi` PC-relative addressing; requires all symbols within any 2 GiB window
- Why `0x80000000` breaks `medlow` on RV64: sign-extending the HI20 field gives `0xFFFFFFFF80000000`, not `0x0000000080000000`
- Primary source: RISC-V psABI spec, code model section
